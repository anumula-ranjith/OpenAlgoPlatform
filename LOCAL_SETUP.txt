STEP 4 - START, STOP AND CHECK
Double-click Start-OpenAlgo.cmd to start the server and open your browser.
The launcher runs the server in the background and avoids a duplicate instance.
Its working directory is always this project folder.
After stopping any strategies, use Stop-OpenAlgo.cmd to stop only the process
started by this project's launcher. This stops the local process; it does not
cancel exchange orders or close broker positions.

PowerShell equivalents, from this folder:
    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\local-openalgo.ps1 -Action Start
    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\local-openalgo.ps1 -Action Status
    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\local-openalgo.ps1 -Action Stop

For a foreground terminal with live logs, first stop the background instance:
    python -m uv run --locked app.py
Stop a foreground instance with Ctrl+C in that terminal.

Read-only installation checks:
    .\.venv\Scripts\python.exe scripts\check-local-openalgo.py
Dependency compatibility:
    python -m uv pip check --python .venv\Scripts\python.exe
Logs:
    log\local-openalgo.stdout.log
    log\local-openalgo.stderr.log
Launcher process record:
    tmp\local-openalgo-process.json

STEP 6 - PREPARE ANGEL ONE SMARTAPI (YOUR BROKER ACCOUNT)
Open https://smartapi.angelone.in and select Login in your own browser.
The verified login entry is:
    https://smartapi.angelone.in/publisher-login/v2/login/
The older smartapi.angelbroking.com/signin address returned a 404 when checked.
Sign in using your registered mobile number or Client ID and the broker's
verification flow. If you already have a key, use its existing app instead of
creating a duplicate. Otherwise, select Add App and follow the current fields.
Save the SmartAPI key privately.
Enable TOTP using the broker's enrollment flow and your authenticator app.
Register your actual static public IP against this app. The current Angel One
notice, effective 01-Apr-2026, requires API order execution to originate from
the registered static IP. A local address such as 127.0.0.1 or 192.168.x.x is
not the public IP to register. This installation does not provision a static IP.
If you already have a SmartAPI key and a static public IP, check their mapping
in the broker dashboard before using the existing app.
Current broker requirements:
    https://smartapi.angelone.in/exchange-regulations
Broker-specific reference:
    https://docs.openalgo.in/connect-brokers/brokers/angelone

STEP 7 - SAVE THE SMARTAPI KEY PRIVATELY
While signed in, open:
    http://127.0.0.1:5000/broker/config?broker=angel
Choose Angel One, enter SmartAPI Key, and Save.
This plugin requires no API secret. Keys saved here are encrypted in the local
database. The current Angel One plugin uses a local TOTP form, not an OAuth
redirect; use the page hints and broker portal requirements for registration.
Do not paste your API key, PIN, password or TOTP into chat or source files.

STEP 8 - CONNECT ANGEL ONE
Open http://127.0.0.1:5000/broker and choose Login with Angel One.
Enter your Client ID, trading PIN and current six-digit TOTP privately.
Wait for the Dashboard and master-contract download. Confirm funds, symbol
search, order book and positions load correctly.
Broker connection and live market data cannot be verified without this login.

STEP 9 - GENERATE YOUR OPENALGO API KEY
Open Profile > API Key at http://127.0.0.1:5000/apikey and generate a key.
This key is different from your Angel One SmartAPI key. Use the OpenAlgo key
with your strategies or integrations and keep it private.

Choose your own test strategy and parameters. Confirm any sandbox order,

STEP 11 - OPTIONAL INTEGRATIONS
TradingView webhooks need a reachable HTTPS endpoint; the loopback address
cannot receive webhooks from TradingView. Configure a documented tunnel or
server only if you choose this workflow. No tunnel or public hosting was added.
Local Python strategies can connect to the local OpenAlgo API directly.
Webhook exposure and live trading are separate from this local installation.

STEP 12 - DAILY USE AND UPDATES
Start OpenAlgo, sign in, reconnect Angel One when its session expires, and
confirm the execution mode and existing positions before enabling strategies.
The default OpenAlgo daily application-session expiry is 03:00 IST.
When updating, stop strategies and the application, back up .env and db/
together, review upstream changes, then update source and sync dependencies.
Do not overwrite an existing .env with .sample.env.
